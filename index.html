Rules
  • One accent per action class: blue for anything that changes data, aqua only for links that leave the page.
  • Status values are colored text, never filled badges, in the page header meta strip.
  • No gradients, no tinted page backgrounds. Grey #F0F0F0 bands are the only non-white surface in content.

Paginated list table — long index screens
For screens that list every record of a type (Newsletters, Activities). No cell borders: a heavy hairline above and below the header row, #EEEEEE between rows, 14px regular column names. Sortable columns carry an arrow that turns blue when active. Controls — range label, rows-per-page select, page numbers — repeat above and below the table so long lists never need a scroll back up.

Which table to use
  • Grid table for a bounded set inside a record — attachments, tapings, faculty on one activity. Never paginated; if it can exceed roughly 20 rows it is the wrong table.
  • Paginated list table for index screens where the row count is open-ended. Always pair it with search and filter chips above the table.
  • Rows per page: 5 / 10 / 25 on nested lists, 10 / 20 / 50 / 100 on full-page indexes. Changing it, sorting, searching, or filtering all reset to page 1.
  • Page numbers collapse with an ellipsis past seven pages; first and last page stay reachable.

ACTIVITY DETAILS (23WC255)

Header
  • 56px, white, hairline bottom. Search + CREATE left, notifications + avatar right.
  • Record-level actions live in the page header, not the top bar.
Page header
  • Plain white — no tinted band.
  • Title, then the meta strip, then actions right: destructive/secondary first, primary last, gear last of all.
  • Read mode shows EDIT; edit mode swaps it for CANCEL + SAVE.
Tab bar
  • Full-width primary blue, equal-width tabs, 13px all caps +0.08em.
  • Active = primary-700 fill, no underline. Hover = 6% white film.
  • Breadcrumb and screen heading sit below the bar, never above.

USEFUL LINKS

Rules
  • Left column is the record being edited; the right rail is only navigation, related records, and external links. Nothing in the rail is required to save the page.
  • One card per subject. Related groups become #F0F0F0 bands inside that card rather than new cards.
  • Fields stack full width; pair them into two columns only when both are short. Helper text belongs to the field, never to the group.
  • Rail starts 37px lower than the form column so its first button aligns with the first card.
  • Feature-flagged sections (Rooms, Follow-ups, ConnectED) render as whole cards, shown or hidden as a unit.

Picker drawer — add or remove records
A drawer, not a modal: anchored to the right edge, full viewport height, 1180px wide (max 96vw), elev-modal, 260ms slide in from the right.
